三个角度看懂 fqc

不是"又一个 gzip"：从格式、算法到架构，每个决定都围绕同一个核心——让压缩后的 FASTQ 可随机访问、可并行、可校验。

压缩格式设计

自包含的块索引归档：索引内嵌在文件尾部，换来 O(log N) 随机访问，无附属索引文件——这是与 BAM/.bai、gzip 流式格式的根本分野。

尾部嵌入索引 跨族 magic 拒绝 codec 分派

压缩算法设计

不压缩"整条记录"，而是把 FASTQ 拆成 4 条流各用最优编解码器；短读段走 ABC 锚基压缩——内建参考基因组（共识），只存差异。

ABC 锚基压缩 SCM 质量编码 读长自适应

高性能架构设计

块 = 独立并行单元：多核并行、随机访问、范围解压、按块校验，四者共享同一个结构决定。三种执行模式产出同一格式，切换只关乎运维。

3 种执行模式 内存有界 零 unsafe

30 秒上手

# 压缩（默认 Archive 最佳压缩比；加 --streaming / --pipeline 换资源权衡）
fqc compress -i reads.fastq -o reads.fqc

# 检视 + 校验（--quick 按块校验，不必全量解码）
fqc info -i reads.fqc --detailed
fqc verify -i reads.fqc --quick

# 解压：全量 / 随机范围提取 / 恢复原始顺序
fqc decompress -i reads.fqc -o out.fastq
fqc decompress -i reads.fqc -o subset.fastq --range 1:1000
fqc decompress -i reads.fqc -o reads.fastq --original-order

为什么值得一看

并行与随机访问，同一个答案

块之间零共享状态——多核并行压缩的同时，也天然获得 O(log N) 随机定位与范围查询。

自包含归档，无附属索引

索引内嵌文件尾部，一个 .fqc 文件即全部——可移植、可搬运，不存在"文件 + 索引"丢失配对的坑。

领域感知，而非通用 LZ

读长自适应：短读走 ABC 共识差分，中长读走 Zstd，质量值走 SCM——每种组件用最懂它的编解码器。

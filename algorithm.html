压缩算法设计

核心思想：不同组件、不同读长，用不同的编解码器。短读段是测序数据的最大头，走 ABC 锚基压缩——不压缩序列本身，而是压缩它相对共识的差异。

组件分离：拆开，再各用最优解

FASTQ 每条记录有四个字段，fqc 不做"整条记录"压缩——拆成 4 条流，各走最懂它的编解码器。这让每种组件独立调优、支持选择性解压（只取需要的组件）。

ID 流

高度可预测（前缀+数字字段）→ tokenize 提取可变数字；模式不稳定则回退 exact，保证无损。

序列流

短读 → ABC 共识差分；中长读 → Zstd。这是压缩比的主要来源。

质量流

占原始数据 ~40%，相邻位置强自相关 → SCM 上下文建模。

辅助流（Aux）

读长等元数据 → Raw / DeltaVarint。

ABC：把参考基因组"内建"进数据

ABC（Anchor-Based Compression）的关键洞见：高覆盖短读数据自带冗余的"参考"——大量近相同的读段。与其对每条序列做统计压缩，不如先把它们归并成一条共识（内建参考），再让每条读段只存"相对共识差在哪"。5 步流水线：

为什么能压：读段不是存成完整序列，而是 (shift, is_rc, mismatches) 三个小字段——绝大多数读段几乎不偏离共识

① Contig 构建：汉明距离分组

与现有 contig 距离 < 阈值 → 并入并更新共识；≥ 阈值 → 新锚点开新 contig；否则标记为孤立读段。高覆盖率是 ABC 收益最大的场景。

② 共识：列比对 + 多数投票

对 contig 内读段逐位置取出现最多的碱基，得到代表序列。这就是"内建参考基因组"——无需任何外部数据。

③④ Delta + 噪声：只存差异

每条读段编码为 shift（对齐位移）、is_rc（是否反向互补）、mismatches（错配位置+替换碱基）。错配碱基用 '0'-'3' 映射 A/C/G/T，Zstd 收尾。

适用边界（诚实标注）：高覆盖短读压缩率可达 10–50×；低覆盖 / 高变异数据下收益显著下降甚至不如 Zstd——此时自动回退 Zstd 兜底路径。ABC 不是万能药，而是"读长自适应"策略里短读那一档。

读长自适应：一个数据里多种策略

fqc 在解析时根据观测到的长度分布自动分类读段，无需 CLI 预设——同一份数据可能同时包含短、中、长读，各走各的路径。

短读 ≤ 511 bp → ABC

高相似性，适合 contig 构建 + 共识差分——压缩率最高的一档。

中读 512 bp–10 KB → Zstd

中等相似性，LZ 族效率更高，直接 Zstd 压缩。

长读 > 10 KB → Zstd 大块

低相似性，大块流式设置追求吞吐。

质量值：默认无损，有损是显式选择

质量值占原始数据约 40%，且同一 run 内相邻位置分数强自相关。SCM 用自适应算术编码 + 上下文建模（order 1/2）+ 位置分箱吃掉这部分冗余。默认 none 模式无损完整保留——有损永远是用户显式选择。

模式做法数据保留
none（默认）无损 Zstd 直接压缩 / SCM完整保留
illumina8Phred 41 分箱为 8 级有损分箱（~20% 体积↓）
qvz固定 8 级最近邻码本量化 → SCM有损（重建为码本 Phred）
discard解码时写占位符丢弃

minimizer 重排：让"像的"挨在一起

压缩的另一个杠杆在顺序：把相似的读段相邻放置，差分编码才更高效。Archive 模式用 minimizer（短 k-mer）做相似性分组后重排读段；重排元数据（Reorder Map）存入归档，解压时按原始顺序恢复——对用户完全透明。

重排只在 Archive 模式启用（Streaming / Pipeline 禁用、保留输入顺序）——这是压缩比 vs 内存的权衡，详见"高性能架构设计"页的三种执行模式。

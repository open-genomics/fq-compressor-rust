压缩算法设计

对不同的 FASTQ 组件与读长类别使用不同的压缩策略：序列走读长自适应编解码器，质量值用 SCM 或量化，ID 用 tokenize，再以 minimizer 重排提升局部性。

1 组件分离：四条独立流

FASTQ 每条记录有四个字段：ID（+注释）、序列、+ 分隔行、质量值。fqc 不做"整条记录"压缩，而是把不同组件拆开，各用最合适的编解码器：

FASTQ 记录流 ├─ ID 流 → Raw / DeltaVarint / DeltaZstd（--id-mode） ├─ 序列流 → AbcV1（短读）/ ZstdPlain（中长读） ├─ 质量值流 → Raw / ScmV1 / ScmOrder1（无损·分箱·量化） └─ 辅助流 → Raw / DeltaVarint（长度等元数据） 每块四条流分别压缩后，写入 Block 的 4 个 payload 区域。

组件分离带来四点优势：每种组件用最优编解码器、独立压缩调优、选择性解压（只取需要的组件）、解压时更好的缓存局部性。

2 读长自适应分类

fqc 在解析时根据观测到的长度分布自动分类读段（而非单一 CLI 预设），不同类别走不同编码路径：

类别长度默认编解码器原理
短读段≤ 511 bpABC（共识 / 差分）高相似性，适合 contig 构建
中等读段512 bp – 10 KBZstd 直接压缩中等相似性，LZ 效率
长读段> 10 KBZstd 大块压缩低相似性，流式效率

3 ABC：锚基压缩（短读段）

ABC（Anchor-Based Compression）把相似读段分组、构建共识序列，再把每条读段编码为相对共识的紧凑差异——类似基于参考的压缩，但参考（共识）内生于数据，无需外部基因组。

输入短读段 │ ① 相似性分组（汉明距离） → ② 构建 Contig → ③ 共识（多数投票） ▼ Delta 编码 (shift, is_rc, mismatches) ▼ 噪声编码 '0'-'3' 替换表示错配 ▼ Zstd 最终压缩

① Contig 构建

读段按汉明距离分组：与现有 contig 距离 < 阈值则并入并更新共识；距离 ≥ 阈值则可作新锚点开新 contig，否则标记为孤立读段。高覆盖率下产生大量"近相同"的读段，是 ABC 收益最大的场景。

② 共识构建

对 contig 内读段做列比对 + 多数投票，逐位置取出现最多的碱基，得到代表序列（consensus）。

列比对 / 多数投票 读段1: A T C G 位置1: A(4) → A 读段2: A T C G 位置2: T(3),C(1) → T 读段3: A C C G 位置3: C(4) → C 读段4: A T C G 位置4: G(4) → G 共识: A T C G

③ Delta 编码

每条读段编码为 (shift, is_rc, mismatches)：shift 对齐位移、is_rc 是否反向互补、mismatches 错配位置与替换碱基列表。

编码组件 共识序列: A T C G A T C G shift = 2（右移 2 位） 读段: - - C G A T T - is_rc = false（正向） mismatches = [(6, A→T)]

④ 噪声编码

错配以紧凑的 '0'-'3' 字符表示替换碱基（A→'0'、C→'1'、G→'2'、T→'3'），位置信息与碱基编码组合。

复杂度：Contig 构建 O(n·m·k)（n 读段数、m 读长、k contig 数），共识构建 O(k·m·c)，Delta 编码 O(n·m)；内存峰值 O(n + k·m)。高覆盖短读段压缩率可达 10–50×，低覆盖/高变异数据显著下降甚至不如 Zstd，此时会回退到 Zstd 兜底路径。

4 质量值压缩：SCM 与量化模式

质量值占原始数据约 40%，且同一 run 内强自相关（相邻位置分数接近）。fqc 提供四种模式：

模式描述数据保留
none（默认）无损 Zstd 直接压缩完整保留
illumina8Phred 41 级量表分箱为 8 级有损分箱（~20% 体积减少）
qvz固定 8 级最近邻码本量化后再走 SCM有损（重建值为码本 Phred）
discard解码时写占位符丢弃

SCM（ScmV1 Order2 / ScmOrder1）是质量流的领域感知编解码器：自适应算术编码 + 上下文建模（order 1/2）+ 位置分箱，利用质量值的强自相关获得比通用 LZ 更高的压缩率。注意：无损模式下仍完整保留所有信息；有损模式是显式选择，默认从不丢质量信息。

5 ID 压缩：Tokenize

读段 ID 通常高度可预测（如 @HWI-EAS100:6:1:2:1824#0/1）。--id-mode 选择编码策略：

模式描述
tokenize（默认）识别公共前缀/后缀，提取可变数字字段；模式不稳定则该块回退 exact
exact始终按原文字符串 + Zstd 存储
discard解码时写占位符 ID

所选模式写入归档 flags，块级可回退，保证 tokenize 失败时无损。

6 重排：minimizer 相似性分组

短单端 Archive 模式会对读段重排以提升 ABC 局部性：提取每条读段的 minimizer（短 k-mer）做相似性分组，相似读段在压缩前相邻放置，使差分编码更高效；重排元数据（Reorder Map）存入归档，解压时按原始顺序恢复。

原始读段顺序 → 相似性分析（minimizer） → 重排后 → 压缩 归档存储重排元数据 → 解压 → 逆重排映射 → 恢复原始顺序
重排只在 Archive 模式下启用（Streaming / Pipeline 禁用、保留输入顺序），这是内存-压缩比权衡的一部分：压缩比 vs 内存占用，详见"高性能架构设计"页的三种执行模式。

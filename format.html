压缩格式设计

一个自描述的块索引归档：索引内嵌在文件尾部，读段按块独立压缩。gzip/zstd 式的流格式无法随机访问；BAM 支持范围查询但要额外的 .bai 索引——fqc 把答案放进归档自身。

完整字节级规范见 docs/reference/format-spec.md

三个关键设计决定

尾部嵌入索引 → O(log N)

索引内嵌归档尾部，按 block_id 二分定位目标块；页脚距 EOF 固定偏移，O(1) 拿元数据。自包含：没有"文件 + 附属索引"的配对问题。

范围查询 = 只解压目标块

块是压缩与随机访问的基本单元。任意读段范围只定位并解码覆盖它的块——--range 1:1000 不解压整个文件。

跨族 magic 拒绝，不猜解码

magic 89 46 51 43 0D 0A 1A 0A（PNG 风格）区分格式族。遇到 C++ 版的 46 51 43 56 32… 返回明确的 unsupported-family 错误——不做启发式猜测，.fqc 扩展名不判定格式。

Block：一个自足的压缩单元

每个 Block = 104 B 固定头 + 4 条压缩流。头部记录每流的偏移/大小与编解码器 ID，reader 可按需读取、独立验证单块——这也是多核并行的单位。

104 B 固定头

block_id、四流 codec ID、块 xxHash64、读段数、统一读长、四流偏移与大小。

4 条组件流

IDs / Seq / Qual / Aux 各用独立编解码器，支持选择性解压。

按块验证

verify --quick 基于归档结构逐块校验，不必全量解码。

Codec 分派：单字节，永不静默回退

编解码器 ID 用 (family << 4) | version 编码：高 4 位是族，低 4 位是版本。遇到未知族返回 unsupported-codec 错误，不回退到默认编解码器——损坏的归档永远显式失败。

流可用族族值
IDsRaw / DeltaVarint / DeltaZstd（按 --id-mode）0x0/0x5/0x4
SeqAbcV1（短读）/ ZstdPlain（中长读）0x1 / 0x7
QualRaw / ScmV1 / ScmOrder10x0 / 0x2 / 0x8
AuxRaw / DeltaVarint0x0 / 0x5

版本与校验：显式契约

主版本精确匹配

reader 只接受 major == 2，无 v1 回退解析路径；主版本不符立即拒绝。次版本容忍、头部按 header_size 跳过扩展字节。

校验和 = 有校验，非"无校验"

每块 xxHash64 + footer 全局校验和；checksum_type 0 表示 XxHash64（seed 0），不是"无校验"。保留字段必须为零且被验证。

格式契约测试锁定字节布局

format_contract 测试 + 冻结 fixture（tests/fixtures/indexed-v2/）保证未来 reader 必须能逐字节一致解码。

为什么是"尾部嵌入索引"：流式压缩（gzip/zstd/DSRC）无法随机访问；基于块的格式（BAM/CRAM）能范围查询但依赖附属索引。fqc 把索引放进归档自身，换来自包含 + 可移植 + 可随机访问——代价是压缩率与随机访问粒度的权衡，块大小即这个权衡的显式旋钮（见"高性能架构设计"）。

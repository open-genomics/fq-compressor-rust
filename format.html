压缩格式设计

自描述的 块索引归档容器：Magic → 全局头 → 独立压缩块 → 可选重排映射 → 块索引 → 页脚。字节布局见本页，完整规范见 docs/reference/format-spec.md 与 openspec/specs/archive-format/。

1 格式族与 Magic 识别

fqc 产品名与 .fqc 扩展名由 Rust 实现（fqc-indexed/v2）与 C++ 实现（fqc-sequential/v2）共享，但两者是不同的格式族——magic 与字节布局不同，不能互相解码。

偏移大小字段值描述
08Magic Bytes89 46 51 43 0D 0A 1A 0Aindexed 格式族标识（PNG 风格签名）
81Version0x20v2.0（(major << 4) | minor）
跨族拒绝是显式行为：reader 打开归档时先做 magic 分派；遇到 C++ fqc-sequential/v2（magic 46 51 43 56 32 0D 0A 1A）返回明确的 unsupported-format-family 错误，不尝试任何启发式猜测解码。扩展名 .fqc 不能判定格式。

2 文件布局总览

Magic Header (9 B) Global Header (变长，最小 34 B) Block 0 ──┬── Block Header (104 B) + 4 条压缩流 (IDs / Seq / Qual / Aux) Block 1 ──┤ … ──┤ Block N ──┘ Reorder Map (可选，变长) Block Index (变长，entry 28 B × N) File Footer (32 B)

块是压缩与随机访问的基本单元：每个块是独立压缩的读段子集，索引记录每块的偏移与读段范围。

3 Global Header

归档元数据：模式标志、读长分类、质量/ID 模式、双端布局、原始文件名与时间戳。

偏移大小字段描述
04header_size头部总大小（u32 LE）
48flags模式标志位（u64 LE）
121compression_algo压缩算法（u8）
131checksum_type校验和类型（u8，0 = XxHash64）
142reserved保留字段（必须为 0）
168total_read_count总读段数（u64 LE）
242filename_len文件名长度（u16 LE）
26Noriginal_filename原始文件名（UTF-8）
26+N8timestamp时间戳（u64 LE）

关键标志位（flags）：IS_PAIRED、PRESERVE_ORDER、QUALITY_MODE、ID_MODE、HAS_REORDER_MAP、PE_LAYOUT、READ_LENGTH_CLASS、STREAMING_MODE。

4 Block：头部与四条流

每个 Block 由一个 104 字节固定头部 + 四条压缩流组成。头部携带校验和、记录数与每条流的偏移/大小，reader 据此按需读取与独立验证单个块。

偏移大小字段描述
04header_size固定 104
44block_id块标识符（u32）
81checksum_type校验和类型
9–124×1codec_ids / codec_seq / codec_qual / codec_aux四流的编解码器 ID
168block_xxhash64块校验和（u64）
244uncompressed_count未压缩读段数
284uniform_read_length统一读长（0 = 可变）
40–704×8offset_ids/seq/qual/aux各流文件偏移（u64）
72–1024×8size_ids/seq/qual/aux各流压缩后大小（u64）

四条流各司其职，分别承载 ID、序列、质量值与辅助元数据（长度等）。这就是"组件级编码"在格式层的落点——每条流可独立选择编解码器。

5 Codec 编码与分派

编解码器以单字节标识，采用 (family << 4) | version 编码：高 4 位是族，低 4 位是版本。读取器先取高 nibble 确定族；遇到未知族返回 unsupported-codec 错误，不回退到默认编解码器。

族值（高 nibble）族名称用途
0x0Raw未压缩原始数据
0x1AbcV1锚基压缩（短读段序列）
0x2ScmV1SCM 质量压缩（Order2）
0x3DeltaLzmaDelta + LZMA
0x4DeltaZstdDelta + Zstd（ID）
0x5DeltaVarintDelta + Varint（ID / 辅助）
0x6OverlapV1重叠压缩
0x7ZstdPlainZstd 直接压缩（中/长读序列）
0x8ScmOrder1SCM 质量压缩（Order1）
0xEExternal外部编解码器
0xFReserved保留
族 → 流的当前映射：IDs = Raw / DeltaVarint / DeltaZstd（按 --id-mode）；Seq = AbcV1（短读）/ ZstdPlain（中长读）；Qual = Raw / ScmV1 / ScmOrder1；Aux = Raw / DeltaVarint。

6 Reorder Map、Block Index 与 File Footer

Reorder Map（可选）

Archive 模式下读段按相似性重排以提升压缩率，归档在文件后段保存 正向/反向置换映射（header 32 B：total_reads、forward_map_size、reverse_map_size），解压时按原始顺序恢复。

Block Index

字段大小描述
header_size / entry_size / num_blocks16 B 头索引元数据
offset8 B块在文件中的偏移（u64）
compressed_size8 B压缩后大小（u64）
archive_id_start8 B起始读段 ID（u64）
read_count4 B读段数量（u32）

File Footer（固定 32 B，位于文件末尾）

字段描述
index_offset（u64）块索引偏移
reorder_map_offset（u64）重排映射偏移（0 = 无）
global_checksum（u64）全局校验和（xxHash64）
magic_end（8 B）结束魔数 FQC_EOF\0
校验和类型 0 表示 XxHash64（seed=0），不表示"无校验"。所有多字节字段为小端序（LE），结构体按紧凑布局读取，保留字段必须为零且被验证。

7 版本兼容与设计动机

版本规则

  • 主版本精确匹配：reader 只接受 major == 2，无 v1 回退解析路径；主版本不符立即拒绝。
  • 次版本容忍：同主版本下不同次版本被接受（当前仅 v2.0）。
  • 扩展容忍：头部字段预留扩展空间，reader 按声明的 header_size 跳过未知额外字节。

为什么是"尾部嵌入索引"

归档自包含：索引内嵌于归档尾部 → 无附属索引文件（对比 BAM 的 .bai） O(log N) 块查找：按 block_id 二分查找 O(1) 元数据访问：页脚距 EOF 固定偏移 范围查询：定位覆盖任意读段范围的块，仅解压目标块 块级验证：verify --quick 可按块校验，不必全量解码

这是压缩比与随机访问之间根本张力的解法：基于流的压缩器（gzip/zstd/DSRC）无法随机访问；基于块的格式（BAM/CRAM）支持范围查询但要额外索引。fqc 把索引放进归档自身，换来 自包含 + 可移植 + 可随机访问的运维能力。
